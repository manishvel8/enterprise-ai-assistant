3. Phase A — Document upload

1

User selects PDF in Documents page

File: frontend/src/app/documents/documents-page/documents-page.component.ts

uploadFile() → ApiService.uploadDocument(file)

Allowed: pdf, docx, pptx, xlsx, csv, txt, png, jpg, jpeg, mp3, mp4, wav · Max 100 MB

Observe: Browser DevTools → Network → POST /api/documents/upload → expect 202 Accepted
2

FastAPI receives multipart upload

File: backend/app/api/documents.py → upload_document()

  • Generates document_id = doc_{uuid12}
  • Calls storage_service.upload_file()
  • Inserts row in Postgres documents (status = PENDING)
  • Enqueues Celery: process_document.delay(document_id, file_name, file_type)
Observe: API terminal logs: Upload received, Stored at: documents/doc_…/original.pdf, Enqueued processing task
3

MinIO stores raw bytes

File: backend/app/services/storage_service.py

Bucket: ai-documents · Key: documents/{document_id}/original.pdf

Postgres storage_path column stores this key (not the display filename).

Observe: http://localhost:9001 → login minioadmin/minioadmin → bucket ai-documents
4

Postgres metadata row created

Table: documents

SELECT document_id, file_name, storage_path, status, chunk_count, created_at
FROM documents ORDER BY created_at DESC LIMIT 5;
Observe: psql -h localhost -p 5433 -U ai_user -d ai_assistant (password: dev_password)
5

Task queued in Redis

Broker: redis://localhost:6379/0 · Queue: document_processing

Observe: redis-cli ping → PONG · Celery worker terminal picks up task within seconds

4. Phase B — Celery worker pipeline

Entry: backend/app/workers/document_worker.py → process_document()

1

Status → PROCESSING

Postgres documents.status updated via _update_status()

2

Download from MinIO

_get_file_bytes() reads storage_path from Postgres, downloads via download_file()

Validates PDF magic bytes %PDF before parsing.

Observe: Worker log: Downloaded file from MinIO: … (N bytes)
3

Parse PDF → content blocks

pipeline/normalizer.py → parsers/pdf_parser.py (PyMuPDF)

Extracts text per page, headings (≥14pt), tables; OCR fallback for scanned pages (Tesseract).

Output: list of ContentBlock with page, section, text.

Observe: Worker log: Pipeline: Parsing PDF → Normalized: N blocks, M characters
4

Normalize / clean

Strips empty blocks, truncates blocks > 50,000 chars.

File: pipeline/normalizer.py

5

Chunking

File: pipeline/chunker.py → chunk_document()

ParameterValue
Max tokens per chunk800
Overlap100 tokens
Min chunk size50 tokens (smaller discarded)
Tokenizertiktoken cl100k_base
Chunk ID{document_id}_chunk_{index}

Metadata on each chunk: page_number, section_title, chunk_index, token_count, file_name.

Observe: Worker log: Chunked 'file.pdf': X blocks → Y chunks [800 max tokens, 100 overlap]
6

Embedding generation

File: pipeline/embedder.py → embed_chunks_sync()

SettingValue
Modeltext-embedding-3-small
Dimensions1536
Batch size100

Each chunk text → one 1536-float vector via OpenAI-compatible gateway.

Observe: Worker log: Pipeline: Embedding N chunks · HTTP POST to /v1/embeddings
7

Store vectors in Qdrant

File: db/vector_store.py → ensure_collection() + store_chunks()

SettingValue
Collection namechunks
Distance metricCosine
Vector size1536
Point IDUUID5 from chunk_id (idempotent re-process)

Payload stored with each vector: chunk_id, document_id, file_name, chunk_text, page_number, section_title, chunk_index, token_count, source_type.

Observe: http://localhost:6333/dashboard → collection chunks → points count increases
8

Save chunk text in Postgres

_save_chunks_postgres() inserts rows into chunks table (full text for audit/debug, not vectors).

SELECT chunk_id, chunk_index, page_number, left(chunk_text, 80) AS preview
FROM chunks WHERE document_id = 'doc_YOUR_ID' ORDER BY chunk_index;
9

Neo4j graph update (GraphRAG, non-fatal if fails)

Files: pipeline/entity_extractor.py, pipeline/graph_store.py, db/neo4j_client.py

Per chunk: LLM extracts entities, relationships, topics, decisions → MERGE into Neo4j.

Node labelsExamples
Document, ChunkOne doc node; one chunk node per chunk
Person, Organization, Topic, Decision, Metric, EntityExtracted by GPT-4o JSON
RelationshipsMENTIONS, BELONGS_TO_TOPIC, RELATED_TO, SUPPORTED_BY
Observe: http://localhost:7474 → neo4j/dev_password
MATCH (d:Document) RETURN d.file_name, d.document_id;
MATCH (c:Chunk {document_id: 'doc_YOUR_ID'}) RETURN c LIMIT 10;
MATCH (c:Chunk)-[r]->(e) RETURN c, r, e LIMIT 25;
10

Status → COMPLETE

Postgres: status=COMPLETE, chunk_count=N. UI polls every 5s and shows green badge.

Observe: Documents page shows complete with chunk count > 0
If chunk_count = 0: Check Celery logs. Common causes: MinIO download failed (missing minio package), invalid PDF bytes, scanned PDF without OCR, or Qdrant client missing. Worker now fails loudly instead of fake-complete.

6. Phase D — User query → answer

Entry: Chat UI http://localhost:4200/chat → POST /api/chat

Orchestrator: backend/app/agents/workflow.py → run_agentic_workflow()

User types question │ ▼ ┌──────────────────┐ │ 1. Router Agent │ Classify intent: doc_question | graph_question | general_chat | summary │ router_agent.py │ Uses GPT-4o. Heuristic: resume/doc keywords → doc_question └────────┬─────────┘ │ (if not general_chat) ▼ ┌──────────────────┐ │ 2. Query Rewrite │ Expand/clarify query using last 4 chat turns │ rewrite_agent.py │ └────────┬─────────┘ ▼ ┌──────────────────┐ │ 3. Retriever │ embed_query() → same model as ingestion (1536-d) │ retriever_agent │ Qdrant cosine search, top_k=5, score_threshold=0.25 │ retriever.py │ Returns RetrievedChunk[] with similarity_score + chunk_text └────────┬─────────┘ │ (graph_question also runs Cypher agent on Neo4j) ▼ ┌──────────────────┐ │ 4. Context │ Merge chunks (+ optional graph results) into numbered context │ Builder │ Max ~15,000 chars. Format: [1] Source: file.pdf, Page 3… │ context_builder │ └────────┬─────────┘ ▼ ┌──────────────────┐ │ 5. Answer Agent │ GPT-4o with RAG_SYSTEM_PROMPT + context + question │ answer_agent.py │ Must cite [1], [2]… Builds SourceCitation list │ rag.py │ └────────┬─────────┘ ▼ ┌──────────────────┐ │ 6. Critic Agent │ Validates answer is grounded in context (no hallucination) │ critic_agent.py │ Up to 3 attempts; rejects if not grounded └────────┬─────────┘ ▼ ┌──────────────────┐ │ 7. Memory Agent │ Save user + assistant messages to Postgres sessions/messages │ memory_agent.py │ └────────┬─────────┘ ▼ ChatResponse: { answer, citations[], debug{} }

What the LLM actually receives (RAG path)

System: You are an enterprise AI assistant… Answer ONLY from context. Cite [1], [2]…

[Last 6 conversation messages]

[2] Source: Resume_BhanuTeja_DS.pdf, Page 2…

During chat (Debug panel)

  1. Open http://localhost:4200/chat → hard refresh (Ctrl+Shift+R)
  2. Click Debug (flask icon, top-right of chat area)
  3. Ask a document-specific question
  4. After answer, debug panel shows:

intentRouter — should be doc_question for resume questions
retrieved_chunks_countRetriever — should be > 0

API test (same pipeline, no UI)

Do NOT open http://localhost:8000/api/chat in browser (GET → Method Not Allowed).

Use Swagger: http://localhost:8000/docs → POST /api/chat → Try it out:

{
  "user_id": "demo",
  "session_id": "demo-e2e",
  "message": "What role and experience does Bhanu Teja have according to the resume?",
  "stream": false
}

Response fields: answer, citations[], debug.intent, debug.retrieved_chunks_count, debug.similarity_scores.
