1. What is MCP? (explain like I’m new)

MCP = Model Context Protocol — an open standard for connecting AI apps to external tools and data.

Analogy: USB for AI tools. Before USB, every mouse/keyboard had a custom plug. USB made one standard. Before MCP, every AI app invented its own way to call “search my docs” or “search the web”. MCP is a shared plug: any compatible client can talk to any compatible server.

MCP is not:

  • Not a large language model
  • Not LangChain / LangGraph (those are orchestration libraries)
  • Not a vector database

MCP is: a protocol (rules + message format) so:

  • A server can advertise tools (“I can search documents”)
  • A client can discover tools and call them
  • Transport can be stdio (subprocess) or HTTP

2. Why does MCP exist?

Without MCP (tight coupling)

LangGraph imports
  qdrant_service.search()
  tavily_service.search()

Cursor cannot reuse those tools
unless you rewrite adapters.

With MCP (loose coupling)

MCP Server exposes:
  search_documents
  web_search

LangGraph  → MCP client → tools
Cursor     → MCP client → same tools
Any agent  → MCP client → same tools

One tool implementation; many AI hosts can use it.

3. Actors & how a call works

Host (Cursor / our FastAPI)→ MCP Client→ Transport (stdio/HTTP)→ MCP Server→ Tool function→ Qdrant / Tavily / …

Typical sequence

  1. Start server (or client spawns it via stdio)
  2. initialize — handshake / protocol version
  3. tools/list — discovery: names, descriptions, JSON schemas
  4. tools/call — invoke with arguments
  5. Server runs Python function → returns text/JSON content

Transports (important)

TransportHowWhen
stdioClient starts server as child process; JSON-RPC on stdin/stdoutCursor, Claude Desktop, our mcp_client.py
streamable-http / SSEServer listens on a portRemote / shared / curl experiments

REST APILangGraphMCP
Purpose Expose HTTP endpoints to apps/browsers Orchestrate multi-step agent graph Standard way for AI hosts to use tools
Who calls it? Any HTTP client Your app invokes the graph MCP-aware clients (Cursor, our client, …)

They stack: LangGraph decides when to search docs vs web. MCP can be how those tools are invoked (optional USE_MCP_TOOLS=true). FastAPI still exposes REST for humans and demos.

6. Technical code walkthrough

Server registers a tool

from mcp.server.mcpserver import MCPServer
mcp = MCPServer("enterprise-rag-mcp")

@mcp.tool(name="search_documents", description="Semantic search over uploaded PDFs...")
def search_documents(query: str, top_k: int = 5) -> str:
    # embed → qdrant → return JSON string
    ...

if __name__ == "__main__":
    mcp.run(transport="stdio")   # or streamable-http

Client discovers + calls

async with stdio_client(StdioServerParameters(...)) as (read, write):
    async with ClientSession(read, write) as session:
        await session.initialize()
        tools = await session.list_tools()     # discovery
        result = await session.call_tool(      # invocation
            "search_documents",
            {"query": "Neha skills", "top_k": 3},
        )

3 Turn off when done learning 
USE_MCP_TOOLS=false

9. Use the same MCP server inside Cursor

Copy mcp_server/cursor-mcp.example.json into your Cursor MCP config (Cursor Settings → MCP), fill real keys from .env, then ask Cursor: “Use search_documents to find Neha’s skills.” 

{
  "mcpServers": {
    "enterprise-rag": {
      "command": ".../langgraph-agent/venv/bin/python",
      "args": ["-m", "mcp_server.server", "--transport", "stdio"],
      "cwd": ".../langgraph-agent",
      "env": { "OPENAI_API_KEY": "...", "TAVILY_API_KEY": "...", "QDRANT_URL": "http://localhost:6333" }
    }
  }
}
Same server, two hosts: FastAPI/LangGraph and Cursor can both use enterprise-rag-mcp without duplicating tool logic.

10. Interview Q&A (speak these)

Q: What is MCP in one sentence?
An open protocol so AI applications can discover and call external tools/data through a standard client–server interface.
Q: How did you use MCP in your project?
I wrapped our RAG (Qdrant) and web search (Tavily) as MCP tools in mcp_server/server.py. A Python MCP client discovers and calls them; FastAPI exposes /api/mcp/tools and /api/mcp/call for hands-on testing. LangGraph can optionally route retrieval through MCP when USE_MCP_TOOLS=true.
Q: MCP vs function calling?
LLM function-calling is how a model chooses a tool schema in a chat completion. MCP is how a host application connects to tool providers in a reusable, host-agnostic way. They often work together: host gets tools via MCP, then offers them to the LLM as callable functions.
Q: Why stdio?
Local security + simplicity: the client starts the server as a subprocess and speaks JSON-RPC on pipes. No open network port required for local IDE integrations like Cursor.
Q: What would you improve for production?
Persistent MCP sessions (not spawn-per-request), auth on HTTP transport, tool allow-lists, timeouts/retries, observability (which tool, latency, errors), and tenant isolation.
