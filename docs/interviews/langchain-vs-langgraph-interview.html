1. Elevator pitch (30 seconds)

“Tell me about your project.”
I built an Enterprise AI Document Assistant. Users upload PDFs in an Angular UI; a Celery worker parses, chunks, embeds, and stores vectors in Qdrant (and entities in Neo4j). Chat goes through a custom multi-agent pipeline (router → rewrite → retrieve → answer → critic → memory) on FastAPI — LangChain-style agents, but orchestrated by our own code, not a LangGraph StateGraph yet.

Separately I built a LangGraph agentic demo that reuses the same Qdrant chunks collection. It has 7 nodes, conditional routing to RAG / Tavily web search / human-in-the-loop, a quality revise loop, and an SSE UI that lights up each node live.
One sentence difference: Enterprise = production-shaped platform (ingest + GraphRAG + Angular). LangGraph = true graph orchestration demo (HITL + web + live node stream) on shared vectors.

3. Document ingestion E2E (enterprise only)

This is the “offline” path that fills the vector DB before any chat.

UI Upload→ POST /api/documents/upload→ MinIO + Postgres PENDING→ Celery worker→ Parse→ Normalize→ Chunk→ Embed→ Qdrant + Neo4j→ COMPLETE

Technical details (interview numbers)

StepWhat / whyKey code
Upload Store original PDF in MinIO; insert Postgres row status=pending; enqueue task (HTTP 202). backend/app/api/documents.py
Parse PyMuPDF (fitz); validate %PDF magic bytes. parsers/pdf_parser.py
Chunk tiktoken cl100k_base: 800 max / 100 overlap / 50 min tokens. Overlap preserves context across boundaries. pipeline/chunker.py
Embed text-embedding-3-small → 1536-d vectors. pipeline/embedder.py
Vector store Qdrant collection chunks, cosine distance. Payload: chunk_text, file_name, document_id, page, section. db/vector_store.py
Graph Extract entities → Neo4j Document/Chunk/Person/Org (GraphRAG enrichment). pipeline/entity_extractor.py, db/neo4j_client.py
“Why chunk with overlap?”
A fact near a chunk boundary can be split. 100-token overlap means neighboring chunks share context, so retrieval still finds the full idea. Trade-off: more storage and slight duplication.
“Why Celery instead of doing it in the API request?”
Parsing + embedding can take minutes. Returning 202 keeps the API fast; the worker processes asynchronously; UI polls status until complete.

4. Enterprise chat — custom multi-agent workflow (LangChain-style)

Important wording for interviews: This stack is agentic and similar to LangChain agent patterns (state in / state out, tool-like retrieval), but orchestration is hand-written Python in run_agentic_workflow() — not a LangGraph StateGraph. We later built real LangGraph in langgraph-agent/.

Flow

User message→ Router→ Rewrite→ Retriever (± Cypher)→ ContextBuilder→ Answer↔ Critic→ Memory

Agents (what each does)

AgentJobFile
RouterIntent: doc_question | graph_question | general_chat | summary. Heuristics fix LLM misroutes (resume words → doc_question).agents/router_agent.py
RewriteClarify query for better retrieval.agents/rewrite_agent.py
RetrieverEmbed query → Qdrant top_k=5, threshold 0.25. Optional GraphRAG mode.agents/retriever_agent.py, db/retriever.py
CypherNeo4j graph questions (entities/relations).agents/cypher_agent.py
ContextBuilderFormat chunks into LLM context + citations.agents/context_builder_agent.py
AnswerGPT-4o grounded answer.agents/answer_agent.py
CriticGroundedness check; if fail → Answer again (max 2).agents/critic_agent.py
MemoryUpsert session + insert user/assistant messages in Postgres.agents/memory_agent.py

API / UI

  • POST /api/chat → full JSON answer + debug metadata
  • Angular Chat page: sessions sidebar, citations, debug panel
  • Documents page: upload + status + chunk counts

Orchestrator: backend/app/agents/workflow.py · API: backend/app/api/chat.py

“How is this like LangChain?”
Same ideas: LLM + tools/retrieval, shared state, chaining steps, critic/retry. Difference: we didn’t use LangChain’s LCEL chains or LangGraph’s graph runtime — each agent is a plain async function mutating a shared state object, called in sequence with if-branches.
“What is GraphRAG here?”
After vector retrieval, we can enrich with Neo4j entities (people, orgs linked to chunks). Useful for “who worked where” style questions that benefit from relationships, not only cosine similarity.

5. LangChain vs LangGraph — conceptual (say this clearly)

LangChain (library / patterns)

  • Building blocks: prompts, models, retrievers, tools, memory
  • Great for linear or lightly branched pipelines
  • “Chain” = step outputs feed next step
  • Agents can call tools in a loop

Our enterprise workflow is in the spirit of LangChain agents, implemented custom.

LangGraph (orchestration runtime)

  • Explicit graph: nodes + edges + state
  • Conditional routing as first-class edges
  • Cycles (quality → regenerate) with retry caps
  • Checkpointer + interrupt() for human-in-the-loop
  • Thread IDs for pause/resume across HTTP requests

Our langgraph-agent/ is real LangGraph.

LangChain focus:  components to call LLMs & tools
LangGraph focus:  how control flow moves between those steps over time

Enterprise app  ≈ custom LangChain-style agent pipeline
langgraph-agent ≈ LangGraph StateGraph with HITL + web + quality loop

6. LangGraph deep dive (7 nodes)

START→ 1 Validator→ 2 Router→ 3 RAG/ 3 Web/ 3 Human→ 6 Generator→ 7 Quality→ END

Quality can loop back to Generator (REVISE) up to max_retries=3.

Shared state (whiteboard)

Every node reads/writes a typed AgentState (langgraph-agent/app/graph/state.py): query fields, route, retrieved docs, web results, human input, evidence, generated answer, quality result, retry_count, execution_trace, errors.

Node cheat-sheet

#NodeTechnical job
1query_validatorStructured LLM output: valid? sanitize? block injection/gibberish → END if invalid.
2routerHeuristics + LLM → rag | web_search | needs_human.
3rag_retrieverEmbed → Qdrant query_points top_k=5, threshold 0.25.
4web_searcherTavily sync client → snippets + URLs.
5human_gateinterrupt() pauses; resume with human text; rewrite search query; set route.
6response_generatorBuild evidence → GPT-4o answer with citations.
7quality_checkerLLM-as-judge PASS/REVISE; force PASS at max retries.

Human-in-the-loop (must explain in interviews)

1. human_gate calls interrupt({ question })
2. LangGraph saves full state in MemorySaver under thread_id
3. API sends SSE event type=interrupt → UI shows purple panel
4. User answers → POST /api/chat/resume { thread_id, human_input }
5. API runs graph.stream(Command(resume=human_input), config)
6. interrupt() returns the human text; graph continues to RAG or Web
Implementation detail we hit in production of this demo: On LangGraph 1.2.x, interrupt() failed under async astream() (“Called get_config outside of a runnable context”). Fix: sync graph.stream() in a worker thread + wrap async nodes with asyncio.run; keep human_gate sync.

9. Interview Q&A bank (speak these)

Q: Walk me through a user asking about a resume.
PDF already ingested → vectors in Qdrant. Enterprise: Router → doc_question → rewrite → retrieve (top 5, ≥0.25) → context → GPT-4o → critic → memory → Angular shows answer + sources. LangGraph: Validator → router(rag) → rag_retriever → response_generator → quality_checker → SSE final with sources; UI highlights each node.
Q: Why LangGraph if you already had agents?
Custom workflow is great for a linear enterprise path. LangGraph adds durable branching, cycles, checkpointer, and interrupt/resume — needed for human-in-the-loop and multi-path (RAG vs web) with clean observability.
Q: How do you prevent infinite revise loops?
Enterprise critic: max 2 retries. LangGraph quality_checker: increment retry_count on REVISE; when retry_count ≥ max_retries (3), force PASS and return best answer.
Q: Cosine similarity — what does 0.25 mean?
With text-embedding-3-small, good enterprise PDF matches often land ~0.30–0.55. Threshold 0.5 dropped real hits (e.g. 0.48). 0.25 filters junk but keeps relevant chunks.
Q: How is Tavily configured?
Free Researcher key (tvly-dev-...) in langgraph-agent/.env as TAVILY_API_KEY, loaded by pydantic Settings → tavily_service.py. Restart uvicorn after change. Health endpoint shows tavily.configured: true.
Q: Security — where are secrets?
Only in .env (gitignored). Never hard-coded. Internal OpenAI gateway base URL and keys stay in env. Don’t paste keys into chats or commits.
Q: What would you harden for production?
Swap MemorySaver → Postgres/SQLite checkpointer; auth on APIs; rate limits; Celery concurrency tuning; observe with LangSmith/Langfuse; pin qdrant-client to server major version; dedicated collections per tenant.
